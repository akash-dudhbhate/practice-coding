or # Python + TypeScript Interview Questions — 2.7 YOE

> Questions collected from real interview lists (golinuxcloud, greatfrontend, kore1, devtoolspro, lastroundai, listiak.dev) targeting ~2–3 years experience: mid-level depth — not fresher trivia, not staff-level architecture. Interviewers at this level check whether you understand *why* things work, can debug real problems, and can model messy real-world data safely.

## PYTHON

### Core language & internals
1. What happens when you run a Python program? (compile → bytecode → interpreter)
2. `is` vs `==` — and why `a = 256; b = 256; a is b` is True but `1000 is 1000` may be False (interning)
3. Mutable vs immutable types — which built-ins are which, and why it matters for function args
4. The mutable default argument bug: `def f(x, items=[])` — why it exists and how to fix it
5. LEGB scope rule — walk through name resolution order
6. What are `*args` and `**kwargs`, and what are the parameter-ordering rules?
7. Shallow copy vs deep copy — when does `list.copy()` still bite you?
8. How does Python manage memory? (reference counting + cyclic garbage collector)
9. What is the GIL, and which workloads does it actually block?
10. Iterators vs generators — write a generator, explain `yield` and laziness
11. What does `__init__` vs `__new__` do? When would you touch `__new__`?
12. Dunder methods you'll actually use: `__repr__`, `__eq__`, `__len__`, `__getitem__`, `__enter__/__exit__`
13. What is a context manager? Write one with `contextlib` and one as a class
14. What are descriptors, and how does `@property` work under the hood?

### Functions, closures, decorators
15. What is a closure? Show `nonlocal` fixing a counter
16. Write a decorator that times a function — then one that takes arguments (`@retry(times=3)`)
17. Why `functools.wraps`? What breaks without it?
18. Explain `map`/`filter`/`reduce` vs comprehensions — which is preferred and why
19. Lambda limits — what can't a lambda do?

### OOP depth
20. `@staticmethod` vs `@classmethod` vs instance method — when each
21. Inheritance vs composition — when does inheritance become the wrong choice?
22. What are abstract base classes (`abc.ABC`)? When use them vs duck typing?
23. What is a dataclass? `@dataclass(frozen=True)` vs a plain class vs NamedTuple
24. How do you implement a singleton in Python — and why is it usually a bad idea?
25. MRO — what does `super()` actually resolve to in multiple inheritance?

### Error handling & code quality
26. Exception handling best practices — why bare `except:` is a bug
27. `try/except/else/finally` — what runs when, and what's `else` for?
28. Custom exceptions — when do you define your own?
29. How do you ensure code quality? (type hints, linters, pre-commit, tests)
30. What does `if __name__ == "__main__"` do and why is it needed?

### Concurrency & performance
31. `threading` vs `multiprocessing` vs `asyncio` — which for CPU-bound vs I/O-bound?
32. How does `asyncio` work under the hood? (event loop, coroutines, `await` suspension points)
33. `async def` vs `def` — what actually changes when you add `async`?
34. How would you optimize a slow Python script? (profile first — cProfile, then algorithm, then I/O, then vectorize/Cython)
35. Why is `"".join(list)` faster than `+=` in a loop?
36. Generators for large files — process a 10GB file that doesn't fit in memory

### Data structures & tricky behavior
37. How are `dict` and `set` implemented? Why is lookup O(1)?
38. Dict ordering guarantee since 3.7 — what changed?
39. Why is `list.append` amortized O(1)?
40. Tricky: `a = [[]]*3; a[0].append(1)` — what prints and why?
41. Tricky: what does `sorted` vs `list.sort` return? `key=` and `reverse=` args
42. Walrus operator `:=` — where does it genuinely help?

### Frameworks & real-world
43. Flask vs Django vs FastAPI — when do you pick each?
44. How does Django ORM / SQLAlchemy simplify DB work? What is the N+1 problem?
45. Build a REST API endpoint — what layers do you separate (route → service → db)?
46. What testing tools have you used? pytest fixtures, `parametrize`, mocking with `unittest.mock`
47. What is dependency injection and how does FastAPI's `Depends` work?
48. How do you handle config/secrets in a Python app? (env vars, pydantic-settings — never hardcode)
49. What modules do you reach for constantly? (collections, itertools, functools, pathlib, json, re)
50. What's the hardest Python bug you've debugged? (be ready with a real story — root cause, how you found it)

## TYPESCRIPT

### Fundamentals
1. What is TypeScript and why use it over plain JS? (compile-time types, tooling, refactors)
2. `interface` vs `type` — what's actually different? (declaration merging, unions, extends)
3. What is type inference, and where should you still annotate explicitly? (module boundaries, public APIs)
4. Union types vs intersection types — `A | B` vs `A & B` with a real example
5. What does `strict` mode actually turn on? (strictNullChecks, noImplicitAny, etc.)
6. `any` vs `unknown` — why `unknown` at boundaries and narrow before use
7. `never` — where does it appear? (exhaustive checks, unreachable code)
8. What is `void` vs `undefined` vs `null`?
9. Optional `?` vs `| undefined` — `name?: string` vs `name: string | undefined` — subtle difference (`exactOptionalPropertyTypes`)
10. Enums vs union of literals — why do many teams ban `enum`?

### Narrowing & type safety
11. What is type narrowing? Show `typeof`, `instanceof`, `in`, custom type guards
12. Write a custom type guard: `function isCat(x: Animal): x is Cat`
13. Discriminated unions — model `Shape = {kind:"circle",r:number} | {kind:"rect",w,h}` and exhaustively switch
14. What does `satisfies` do that a plain annotation doesn't? (keeps literal inference)
15. `as` casts — when are they lying? What's safer? (narrowing, Zod/validation at runtime boundary)
16. Type assertion vs type guard — which survives refactoring?
17. What does TypeScript NOT guarantee at runtime? (types are erased — external JSON needs validation)

### Generics
18. Write a generic function `function identity<T>(x: T): T` — why not just `any`?
19. Generic constraints: `<T extends { id: number }>` — write `getById`
20. `keyof` — type a function `getProp<T, K extends keyof T>(obj: T, key: K): T[K]`
21. `typeof` in type position — `const config = {...}; type Config = typeof config`
22. Default generic params — `<T = string>` when is it useful?
23. Generic interfaces/classes — `interface ApiResponse<T> { data: T; error?: string }`

### Utility types & mapped types
24. `Partial`, `Required`, `Readonly`, `Pick`, `Omit` — implement `Partial<T>` yourself with a mapped type
25. `Record<K, V>` — when better than `{[key: string]: V}`?
26. `ReturnType`, `Parameters`, `Awaited` — extract a function's return type
27. `Exclude`, `Extract`, `NonNullable` — filtering union members
28. Mapped types: `{[K in keyof T]: T[K]}` — write `Mutable<T>` that strips `readonly`
29. `as const` — what does it do to literals and objects?

### Functions, classes, modules
30. Function overloads vs union params — when overloads are worth it
31. `readonly` properties and `ReadonlyArray` — where immutability helps
32. Access modifiers: `private` vs `#private` — TS-private vs real-private
33. `abstract class` vs `interface` — when each
34. What are `declare`, ambient types, and `.d.ts` files?
35. `import type` — why does it exist? (isolatedModules, no runtime import)

### Async, errors & real-world typing
36. Type a fetch wrapper: `async function get<T>(url: string): Promise<T>` — what's wrong with it? (T is a lie without runtime validation)
37. Type `Promise` chains and `Promise.all` — `Promise<[User, Post[]]>` tuple results
38. Typing event handlers and callbacks — `React.MouseEvent`, `(e: ChangeEvent<HTMLInputElement>) => void`
39. Type a Node/Express handler or Fastify route — generics on request/response
40. Error handling in typed code — `catch (e: unknown)`, narrowing errors, typed Result pattern
41. JSON from an API is `unknown` — how do you handle it safely? (narrow, or Zod/io-ts parse)
42. Type a debounce/throttle utility preserving the wrapped function's signature
43. Conditional types intro — `T extends string ? A : B` and `infer` — where have you seen them? (built-in utilities use them)
44. tsconfig flags you should know: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`
45. TypeScript + React: typing props, children (`React.ReactNode`), `useState<T>`, `useRef`, generic components

## CROSS-CUTTING (both languages, real-world)
1. Both are "typed" — Python type hints vs TypeScript types: what's enforced at runtime? (neither — TS erases, Python ignores hints; both need runtime validation at boundaries)
2. Python `pydantic` ↔ TypeScript `zod` — same job: parse untrusted data into typed shapes
3. Static analysis: `mypy`/`pyright` ↔ `tsc` — strict mode in each
4. Project setup you'd defend in an interview: lint (ruff/eslint), format (black/prettier), tests (pytest/vitest), CI checks

## LIKELY FOLLOW-UP TRAPS (they ask these after you answer)
- After "what's a decorator": *"now write one that takes arguments"*
- After `any` vs `unknown`: *"give a real example where `as` broke prod"*
- After "GIL": *"so how would you speed up a CPU-bound script — threads won't help, what will?"*
- After `interface` vs `type`: *"which one for a public library API and why?"* (interface — declaration merging)
- After generators: *"write a generator that paginates an API until empty"*
- After generics: *"constrain it — the arg must have an `id`"*
